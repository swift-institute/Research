## Implementation-agent mandate

You are the implementation agent. Execute every authorized task in this document from 00 through 7, including issue/branch/PR/merge/read-back/fleet convergence and the final receipt. Use Claude Code ultracode as the coordinating execution mode. Parallelize only independent exact-owner tasks, preserve one visible mutation task per repository transaction, and keep the programme Goal and completion receipt current throughout execution.

Do not load, attach, cite, reconcile against, or re-import any prior CI/CD document, CSV, or JSON. >

>
> ```text
> ordinary package .github/workflows/ci.yml
>     → runnerless layer wrapper @main
>         → universal Institute workflow @main
>             → common + layer-required CI + documentation
>                 → one complete public aggregate
>

### 1.1 Mutation protocol for every authorized task

1. Start a fresh, separately visible Claude Code task in the configured local project environment.
2. Load this document and current Skills before extensive source inspection.
3. Run `gh auth status`, `gh api /user`, and an authenticated REST read of the intended repository.
4. Resolve the default branch, visibility, exact head, Actions enabled state, and owner Issue state.
5. Inspect shared checkout state. Never checkout, restore, reset, stash, clean, or delete another session’s work. Use a new clone/worktree only when safe and authorized.
6. Read the complete owner Issue and comments. Search for an already-open exact duplicate before filing a new work object.
7. Create/reuse exactly the work object named by the task; assign the executing principal identity while the work is in flight; link it as a native sub-issue of the programme Goal where applicable.
8. Create an isolated feature branch from the exact read-back head.
9. Build and inspect the complete intended mutation. Keep one semantic transaction per PR.
10. Put this statement in every programme PR body:

   > **Programme exemption from #113:** the principal expressly scoped `swift-institute/.github#113` out of this CI/CD refactor. Existing Python/shell may be repaired or rewritten, and new executable logic may use the narrowest correct owner. This PR is governed by the definitive CI/CD implementation programme; `#246` remains the separate record that the general no-new-debt rule is mechanically unenforced.

11. Run the task’s failing fixture/positive control before or against the change, then its conforming/negative control through the same instrument.
12. Run local owner tests through Workspace. Use `--fresh` when the result will be cited as newly originated evidence.
13. Stage explicit paths only. Re-read staged paths, tracked unstaged content, untracked content, and the committed blobs before push.
14. Open one PR. Do not use an auto-closing trailer when completion requires post-merge CI evidence.
15. Read review and CI at run level. Address exact findings with follow-up commits; do not force-push.
16. Merge only when protected-main requirements and required review are satisfied.
17. Read the default-branch head back and prove it contains the intended blobs.
18. Dispatch the task’s fresh full-tier or control-plane verification at the merged exact head. Never use `gh run rerun` for closure.
19. Read the run object’s own `conclusion`, `head_sha`, `event`, `run_attempt`, and `referenced_workflows`; inspect only the jobs needed to establish the predicate.
20. Read every mutated live setting/check/ruleset/status back through authenticated REST.
21. Close a human work object only after its stated evidence exists; let bot-owned issues close themselves.
22. Record the task, controls, run IDs, heads, files, live read-back, and rollback in the completion receipt.
23. End that mutation task. Start a fresh task for a different exact owner.
